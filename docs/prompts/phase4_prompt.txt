# MARS PATHFINDER — PHASE 4: MACHINE LEARNING & PREDICTIVE ANALYTICS

## 1. ROLE

Act as a senior machine learning researcher, planetary scientist, computer vision engineer, atmospheric data scientist, geospatial AI engineer and MLOps architect.

You are extending the existing Mars Pathfinder platform.

Phase 4 introduces scientifically validated machine learning and predictive analytics.

Do not create artificial claims of predictive accuracy.

Every model must have appropriate training data, validation data, independent testing and documented limitations.

Inspect:

## 4. MODEL 1: TERRAIN CLASSIFICATION

Build a computer vision model to classify Mars surface imagery.

Possible classes:

- Rocky terrain.
- Sand-covered terrain.
- Craters.
- Boulders.
- Cliffs.
- Slopes.
- Flat terrain.
- Geological formations.

Investigate suitable NASA HiRISE imagery and annotated datasets.

Potential architectures:

- U-Net.
- DeepLabV3+.
- ResNet-based classifiers.
- Vision transformers where justified.

Requirements:

- Dataset documentation.
- Image preprocessing.
- Annotation strategy.
- Training.
- Validation.
- Independent testing.
- Confusion matrix.
- Precision.
- Recall.
- F1 score.
- Intersection over Union for segmentation.

Display model detections on the Mars map.

Do not claim that the model identifies hazards reliably unless independent testing supports that claim.

## 6. MODEL 3: ATMOSPHERIC TIME-SERIES ANALYSIS

Investigate historical MEDA and MCS observations.

Develop models for:

- Atmospheric temperature trends.
- Pressure variations.
- Dust opacity trends.
- Seasonal patterns.
- Atmospheric vertical profiles where suitable.
- Wind patterns where sufficient observations exist.

Potential models:

- LSTM.
- GRU.
- Temporal convolutional networks.
- Temporal Fusion Transformer.
- Statistical forecasting baselines.

Compare neural networks against simpler statistical baselines.

Use time-aware train, validation and test splits.

Never randomly split highly correlated time-series observations in a way that causes data leakage.

## 11. MODEL EVALUATION AND SCIENTIFIC VALIDATION

Every model must have:

- Dataset source.
- Dataset version.
- Data preprocessing description.
- Training methodology.
- Validation methodology.
- Independent test results.
- Model architecture.
- Hyperparameters.
- Evaluation metrics.
- Confidence and uncertainty reporting.
- Known limitations.

Check for:

- Data leakage.
- Class imbalance.
- Overfitting.
- Spatial generalization problems.
- Temporal leakage.
- Instrument calibration differences.
- Missing values.
- Dataset bias.

Compare against appropriate baseline models.

Never fabricate evaluation metrics.
